# BEN-32 — Welcome email: DSFR pictograms next to the three feature blocks

## Setup and assumptions

BEN-32 adds a decorative icon to the left of each of the welcome email's three feature block titles. Source of truth: `.agents/tasks/BEN-32/issue.md` and `plan.md`. The plan's decisions are final: the DSFR tab icons from `ProjectPageTabs.tsx`, exported as 48×48 PNGs shown at 24×24 in `#000091`, hosted under `apps/web/public/img/emails/`, with URLs built from `WEBAPP_URL`. This guide was written before implementation. Run it once BEN-32 is implemented in this worktree.

Unlike 01 and 02, this guide **rebuilds** the `api` and `web` containers once (S1): the PNGs ship in the web image and the template ships in the api image. The Postgres volume survives the rebuild. Never run `make e2e-down -v`.

Fixed facts about the stack and the change, taken from `.env.e2e`, `docker-compose.e2e.yml` and the plan:

- Web app / API (proxied): `http://localhost:3001`, which is also the `WEBAPP_URL` in `.env.e2e`. `POST /api/auth/register` registers a user and sends the welcome email inline (the kill switch is on in the `api` container).
- MailCatcher UI/API: `http://localhost:1081`. From the host, SMTP is on port `1026` (`SMTP_PORT` in `.env.e2e`). The `api` container uses `mailcatcher:1025`.
- Icons, in block order (plan §1):
  - `Votre évaluation des impacts`: `fr-icon-bar-chart-box-line`, file `impacts-evaluation.png`
  - `Votre analyse coût-bénéfice`: `fr-icon-line-chart-line`, file `cost-benefit-analysis.png`
  - `Votre analyse des coûts évités`: `fr-icon-money-euro-box-line`, file `avoided-costs-analysis.png`
- Each icon is served at `${WEBAPP_URL}/img/emails/<file>`.
- Expected tag (plan §2), shown here for the first icon: `<img src="http://localhost:3001/img/emails/impacts-evaluation.png" width="24" height="24" alt="" border="0" style="display:block;width:24px;height:24px;border:0;outline:none;text-decoration:none;">`. It sits in `<td width="24" valign="middle" …>`, next to a `<td valign="middle" …>` that holds the title.
- nginx (`apps/web/scalingo/nginx.conf.erb`, also used by the e2e web image) uses `try_files $uri $uri/ /index.html`, so a missing file returns **`200 text/html`** (the SPA), never a 404. A `200` status alone proves nothing. Always check the content type.
- 01 S12 step 5 ("no images", expects `0`) no longer holds for the welcome email, which now has 3 `<img>`. The reminders (05, 06) still expect `0`.

The commands use `curl`, `jq`, `file`, `cmp`, `perl`, `docker compose`, Chrome with DevTools and Safari. Run everything from the repository root, in **one shell session** (bash or zsh). Define once:

```bash
QA=/tmp/qa08; mkdir -p "$QA"
WEBAPP_URL=http://localhost:3001
ICONS=(impacts-evaluation cost-benefit-analysis avoided-costs-analysis)  # an array: zsh does not word-split "$ICONS"
PREVIEW=./dist/src/notifications/adapters/primary/sendLifecycleEmailPreview.script.js
dc() { docker compose --env-file .env.e2e -f docker-compose.e2e.yml "$@"; }

# Register a fresh user (sends the welcome email); sets USER_ID and EMAIL, prints the HTTP status.
register() {
  USER_ID=$(uuidgen | tr 'A-Z' 'a-z')
  EMAIL="qa-lifecycle08-$(date +%s)-$RANDOM@example.com"
  curl -s -o /dev/null -w '%{http_code}\n' -X POST "$WEBAPP_URL/api/auth/register" -H "Content-Type: application/json" \
    -d "{\"id\":\"$USER_ID\",\"email\":\"$EMAIL\",\"firstName\":\"Jean\",\"lastName\":\"Dupont\",\"structureType\":\"company\",\"structureActivity\":\"other\",\"structureName\":\"ADEME\",\"personalDataStorageConsented\":true,\"personalDataAnalyticsUseConsented\":false,\"personalDataCommunicationUseConsented\":false,\"subscribedToNewsletter\":false}"
}
# Newest welcome email to an address (MailCatcher is never purged: always filter on the exact subject).
welcome_id() {
  curl -s http://localhost:1081/messages | jq -r --arg email "$1" \
    '[.[] | select(.subject == "Bienvenue chez Bénéfriches" and (.recipients[] | contains($email)))] | max_by(.id) | .id'
}
# save <message id> <address> <name>: writes $QA/<name>.html and $QA/<name>.txt, with the address and
# the unsubscribe token normalised so that two emails can be diffed.
save() {
  for part in html plain; do
    curl -s "http://localhost:1081/messages/$1.$part" | tr -d '\r' \
      | sed -e "s/$2/EMAIL/g" -E -e 's/token=[A-Za-z0-9._-]+/token=TOKEN/g' > "$QA/$3.${part/plain/txt}"
  done
}
# One line per icon: "<src> -> <title in the same row>".
icon_titles() { perl -0ne 'while (/<img[^>]*src="([^"]+)".*?<td[^>]*>\s*([^<]*?)\s*<\/td>/gs) { print "$1 -> $2\n" }' "$1"; }
# Preview script run on the host, against the e2e Postgres and MailCatcher (env as in 02 Setup).
# Set PREVIEW_WEBAPP_URL to override WEBAPP_URL for one run.
preview() {
  ( set -a; . ./.env.e2e; unset DATABASE_URL; SMTP_HOST=localhost
    WEBAPP_URL=${PREVIEW_WEBAPP_URL:-$WEBAPP_URL}; set +a
    cd apps/api && node "$PREVIEW" "$@" )
}
```

## S0 — Baseline welcome email before the rebuild (recommended)

2. In the DevTools console, run:
   ```js
   [...document.images].map((i) => { const r = i.getBoundingClientRect(), t = i.closest("td").nextElementSibling.getBoundingClientRect(); return [i.naturalWidth, i.naturalHeight, r.width, r.height, r.right <= t.left, Math.round((r.top + r.bottom - t.top - t.bottom) / 2)]; })
   ```

## S5 — Images blocked: the layout stays intact and no alt text shows

1. In the S4 tab, open DevTools → ⋮ → More tools → Network request blocking, add the pattern `*/img/emails/*`, enable it and reload. Observe: three requests marked `blocked:devtools` in Network; no alt text; the titles keep their position (the 24px box and the gap stay reserved) and the email reads normally. Chrome draws its small broken-image glyph inside each 24×24 box: Chromium does this for any `<img>` with an explicit size whose load fails, whatever its `alt`, and the explicit `width`/`height` are required for Outlook. That glyph is browser behaviour on a failed request, not what a mail client shows when it blocks images (it never requests them): the client check is Deferred step 4. Re-run the S4 snippet: three `[0, 0, 24, 24, true, 0]`. Then turn request blocking off.
2. Check the same thing with dead URLs in another engine:
   ```bash
   sed 's#http://localhost:3001/img/emails/#http://127.0.0.1:9/img/emails/#g' "$QA/after.html" > "$QA/dead-images.html"
   open -a Safari "$QA/dead-images.html"
   ```
   Observe: the same layout as step 1: no alt text, titles in place, the 24px box and the gap reserved (Safari runs on WebKit, the engine Apple Mail uses). Note whether WebKit draws a placeholder glyph in the box, and report it on BEN-32. The `EMAIL` and `TOKEN` placeholders are expected because the file is normalised.
