## Setup and assumptions

The e2e stack (`docker-compose.e2e.yml` + `.env.e2e`, from the repository root) must run images **built from this branch after BEN-31 was implemented**: `make e2e-up-build`. Both images change: `api` (signature) and `web` (unsubscribe page). S0 checks it. The guide never restarts or stops a container; no migration and no new environment variable come with this ticket.

Fixed facts about this running stack, taken from `.env.e2e` / `docker-compose.e2e.yml`:

- Web app / API (proxied): `http://localhost:3001` (`WEBAPP_URL`). `POST /api/auth/register` registers a user (used by S4 only). The unsubscribe page is `/emails/desinscription?token=…`; on load it calls `POST /api/lifecycle-emails/unsubscribe` (throttled to 10 requests per minute: on a `429`, wait a minute and retry).
- MailCatcher UI/API: `http://localhost:1081`. It is never purged between runs: always look messages up by recipient and subject.
- Postgres: `postgresql://postgres:e2e-tests-password@localhost:5433/benefriches_e2e_tests_db`.
- Inside the `api` container (working directory `/app/apps/api`, `dist/` built): `LIFECYCLE_EMAILS_ENABLED=true` and the fake contact `Mathilde` / `Lefèvre` / `Chargée de déploiement` / `01 23 45 67 89` / `mathilde.lefevre@example.com`.
- The preview script (`--type=first-site-reminder` sends one sample, `--type=first-project-reminder` sends two: the friche `Ancienne carrière d’argile de Blajan` and the non-friche `Exploitation agricole des Quatre Chemins`) renders through the same builders as the daily job and the retry sweeper. Its sample recipient is `Camille Durand`; its unsubscribe link is signed for the sample user `00000000-0000-4000-8000-000000000000`, which matches no account, so opening it shows the real confirmation page and writes nothing (03 S13).

Commands use `curl`, `jq`, `psql` and `docker compose`. Run everything from the repository root, in **one shell session** (works in bash and zsh). Define once:

```bash
DB="postgresql://postgres:e2e-tests-password@localhost:5433/benefriches_e2e_tests_db"
dc() { docker compose --env-file .env.e2e -f docker-compose.e2e.yml "$@"; }
PREVIEW=./dist/src/notifications/adapters/primary/sendLifecycleEmailPreview.script.js
JOB=./dist/src/notifications/adapters/primary/sendDailyLifecycleReminders.script.js
P_EMAIL="qa-lifecycle09-preview-$(date +%s)-$RANDOM@example.com"

# Newest message to address $1 whose subject (NBSP turned into a space) starts with $2.
msg_id() {
  curl -s http://localhost:1081/messages | jq -r --arg e "$1" --arg s "$2" \
    '[.[] | select((.subject | gsub("\u00a0"; " ") | startswith($s)) and any(.recipients[]; contains($e)))] | max_by(.id) | .id'
}
# Save message $1's parts as /tmp/qa09-$2.txt and /tmp/qa09-$2.html (CRs stripped).
fetch() {
  curl -s "http://localhost:1081/messages/$1.plain" | tr -d '\r' > "/tmp/qa09-$2.txt"
  curl -s "http://localhost:1081/messages/$1.html" | tr -d '\r' > "/tmp/qa09-$2.html"
}
# Every link of a saved message: the HTML hrefs, then the URLs of the plain-text part.
links() {
  echo "-- html"; tr -d '\n' < "/tmp/qa09-$1.html" | grep -oE 'href="[^"]*"'
  echo "-- text"; grep -oE '(https?|mailto):[^ ]+' "/tmp/qa09-$1.txt"
}
# The signature block of a saved message, in both parts (HTML with inline styles removed).
signature() {
  echo "-- html"; grep -A4 -F 'Mathilde Lefèvre<br>' "/tmp/qa09-$1.html" | sed -E 's/^ +//; s/ style="[^"]*"//g'
  echo "-- text"; grep -A4 -xF 'Mathilde Lefèvre' "/tmp/qa09-$1.txt"
}
# No link to the bare WEBAPP_URL, in either part: prints "html=0 text=0" when clean.
no_webapp_link() {
  echo "html=$(grep -cE 'href="http://localhost:3001/?"' "/tmp/qa09-$1.html") text=$(grep -cxE 'https?://localhost:3001/?|.*Externe.*https?://.*' "/tmp/qa09-$1.txt")"
}
```

Browser checks use a **private window** (no Bénéfriches session) with DevTools open on the **Network** tab.
