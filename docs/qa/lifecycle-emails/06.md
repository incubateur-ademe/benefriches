## Setup and assumptions

The app is already running at `http://localhost:3001` (the e2e stack, `docker-compose.e2e.yml` + `.env.e2e`, from the repository root). It must have been **built from this branch after ticket 06 was implemented** (`make e2e-up-build`): the `api` image then contains the daily job with both reminder use cases. No migration and no new environment variable come with this ticket (plan D10): the contact configuration, the kill switch and the unsubscribe secret are ticket 05's.

Like 05, S15 **stops and starts the `mailcatcher` container** to simulate a mail outage (`dc stop mailcatcher` / `dc start mailcatcher`). MailCatcher keeps messages in memory, so the restart empties its inbox and restarts message ids at 1: run S2–S4 (which read earlier messages) before S15. The guide never restarts, rebuilds or stops the `api`, `web` or `postgres` containers. Always finish a scenario with MailCatcher back up.

Fixed facts about this running stack, taken from `.env.e2e` / `docker-compose.e2e.yml` and the plan (`.agents/tasks/lifecycle-emails/issues/06-first-project-reminder.plan.md`):

- Web app / API (proxied): `http://localhost:3001`. `POST /api/auth/register` registers a user (and sends the welcome email inline); the response sets the access-token cookie. `POST /api/sites/create-express` creates an express site (`FRICHE`, `AGRICULTURAL_OPERATION` or `NATURAL_AREA`); `POST /api/sites/:siteId/archive` archives it. `POST /api/reconversion-projects/create-from-template` (authenticated) creates an express project on a site; `POST /api/reconversion-projects/:id/archive` archives it. `POST /api/lifecycle-emails/unsubscribe` (ticket 03) unsubscribes.
- MailCatcher UI/API: `http://localhost:1081`. The `api` container reaches it as `SMTP_HOST=mailcatcher`.
- Postgres: `postgresql://postgres:e2e-tests-password@localhost:5433/benefriches_e2e_tests_db`. The volume persists across runs: the database already holds sites from earlier e2e runs and QA sessions, some of them inside the 24–72 h window. S0 drains them.
- Inside the running `api` container: `LIFECYCLE_EMAILS_ENABLED=true`, `LIFECYCLE_EMAILS_UNSUBSCRIBE_SECRET=e2e-tests-unsubscribe-secret`, `WEBAPP_URL=http://localhost:3001`, and the fake contact from 05: `Mathilde` / `Lefèvre` / `Chargée de déploiement` / `01 23 45 67 89` / `mathilde.lefevre@example.com`.
- Daily job: `apps/api/src/notifications/adapters/primary/sendDailyLifecycleReminders.script.ts`, compiled to `dist/src/notifications/adapters/primary/sendDailyLifecycleReminders.script.js`. One flag: `--dry-run`. It now runs `SendFirstSiteRemindersUseCase` then `SendFirstProjectRemindersUseCase`, each in its own `try/catch` (plan D5).
- Log lines of the new cohort (plan D5), the dry-run ones prefixed with `[DRY RUN] `:
  - window: `First project reminders: sites created after <now − 72 h, ISO> and at or before <now − 24 h, ISO>`
  - dry run, one per **site**: `[DRY RUN] Eligible for first project reminder: siteId=…, siteName=…, siteNature=…, userId=…, email=…, siteCreatedAt=<ISO>`
  - contact missing (`warn`): `Lifecycle email contact is not configured (LIFECYCLE_EMAILS_CONTACT_*): first project reminders not sent`
  - per-site error: `First project reminder failed for site <siteId> (user <userId>)`
  - summary (`eligible` counts sites): `First project reminder summary: eligible=N, sent=N, failed=N, skippedDisabled=N, skippedUnsubscribed=N, skippedAlreadySent=N, skippedContactNotConfigured=N, errored=N`
- Eligibility (plan D2), scoped to a **site**: `sites.created_at > now − 72 h` and `<= now − 24 h` (the **site's** creation, not the user's registration); `creation_mode IN ('custom', 'express')` (so `csv-import` and a NULL legacy value never trigger); `status = 'active'`; owner not unsubscribed; **no reconversion project on the site**, whatever its status; **no `first-project-reminder` ledger row for that site** (`related_entity_id = sites.id`), in any status. One row per site, never grouped by user. The ledger row is entity-scoped (`related_entity_id` = the site id).
- Email (plan D7): subject `<site name> : et si vous renseigniez votre projet d’aménagement ?` (non-breaking spaces before `:` and `?`, name whitespace-collapsed); primary CTA `Renseigner mon projet` → `${WEBAPP_URL}/creer-projet?siteId=<site id>`; § 1 depends on the nature (`une friche` / `cette friche` for a `FRICHE`, `un site` / `ce site` for every other nature). **The mockup's friche-only compatibility offer (the "Vous ne savez pas encore…" paragraph and the `Découvrir la compatibilité de ma friche` button) is dropped for v1** (plan D8, user decision 2026-09-29: no page evaluates compatibility for an existing site). No email may contain it, friche or not; the guide checks its absence everywhere, and a visual comparison with the mockup must not flag it as missing.
- Nothing runs the job or the sweeper automatically on this stack (no cron locally): every email and ledger row below comes from the step you just ran.

Commands use `curl`, `jq`, `psql`, `openssl`, `perl` and `docker compose`. Run everything from the repository root, in **one shell session** (the scenarios reuse variables and functions; the snippets work in bash and zsh). Define once:

```bash
DB="postgresql://postgres:e2e-tests-password@localhost:5433/benefriches_e2e_tests_db"
dc() { docker compose --env-file .env.e2e -f docker-compose.e2e.yml "$@"; }
JOB=./dist/src/notifications/adapters/primary/sendDailyLifecycleReminders.script.js
SWEEPER=./dist/src/notifications/adapters/primary/retryLifecycleEmailDeliveries.script.js
PREVIEW=./dist/src/notifications/adapters/primary/sendLifecycleEmailPreview.script.js
PR_SUFFIX=' : et si vous renseigniez votre projet d’aménagement ?'   # compared after turning NBSP into a space

# Run the daily job inside the api container (same env as the running API).
# Usage: job [-e VAR=value ...] [--dry-run]. The -e overrides apply to that one process only.
# Prints the job's own lines (both cohorts) and the exit code; the full output is in /tmp/job.log (ANSI colours stripped).
job() {
  local opts=()
  while [ "$1" = "-e" ]; do opts+=(-e "$2"); shift 2; done
  dc exec -T "${opts[@]}" api node "$JOB" "$@" > /tmp/job.log 2>&1; local rc=$?; perl -pi -e "s/\e\[[0-9;]*m//g" /tmp/job.log
  grep -iE 'first (site|project) reminder|contact is not configured|sendDailyLifecycleReminders' /tmp/job.log
  echo "exit code: $rc"
}
# 1 if the last job run listed this site as eligible (dry run), else 0.
listed() { grep -cF "Eligible for first project reminder: siteId=${1:-$SITE_ID}," /tmp/job.log; }
# The first project reminder summary line of the last job run.
psummary() { grep -o 'First project reminder summary: .*' /tmp/job.log; }

# Run the retry sweeper (ticket 04), same override convention as job.
sweep() {
  local opts=()
  while [ "$1" = "-e" ]; do opts+=(-e "$2"); shift 2; done
  dc exec -T "${opts[@]}" api node "$SWEEPER" > /tmp/sweep.log 2>&1; local rc=$?; perl -pi -e "s/\e\[[0-9;]*m//g" /tmp/sweep.log
  grep -E 'retry summary|Retry failed' /tmp/sweep.log; echo "exit code: $rc"
}
mc_down() { dc stop mailcatcher; }
mc_up() { dc start mailcatcher && until curl -sf -o /dev/null http://localhost:1081/messages; do sleep 1; done; echo "mailcatcher up"; }

# Move a user's registration into the past: backdate <hours> [minutes] [user id].
backdate() {
  psql "$DB" -At -c "UPDATE users SET created_at = now() - interval '$1 hours ${2:-0} minutes' WHERE id = '${3:-$USER_ID}' RETURNING created_at;"
}
# Create an express site for the current user through the real API: express_site <FRICHE|AGRICULTURAL_OPERATION|NATURAL_AREA>.
# Sets and prints SITE_ID. The site is created now: age it with age_site.
express_site() {
  local extra
  case "$1" in
    FRICHE) extra='"fricheActivity": "RAILWAY"' ;;
    AGRICULTURAL_OPERATION) extra='"activity": "CEREALS_AND_OILSEEDS_CULTIVATION"' ;;
    NATURAL_AREA) extra='"type": "FOREST"' ;;
  esac
  SITE_ID=$(uuidgen | tr 'A-Z' 'a-z')
  local code=$(curl -s -b "$JAR" -o /dev/null -w '%{http_code}' -X POST http://localhost:3001/api/sites/create-express \
    -H "Content-Type: application/json" \
    -d "{\"id\": \"$SITE_ID\", \"createdBy\": \"$USER_ID\", \"nature\": \"$1\", $extra, \"surfaceArea\": 15000,
         \"address\": {\"banId\": \"31070\", \"value\": \"Blajan\", \"city\": \"Blajan\", \"cityCode\": \"31070\", \"postCode\": \"31350\", \"long\": 0.652416, \"lat\": 43.260128}}")
  [ "$code" = 201 ] && echo "$SITE_ID" || echo "create-express failed: $code" >&2
}
# Insert a site in SQL, already 36 h old: add_site <creation_mode> <status> [nature] [name] [user id].

add_site() {
  SITE_ID=$(uuidgen | tr 'A-Z' 'a-z')
  psql "$DB" -q -c "INSERT INTO sites (id, name, created_by, creation_mode, nature, surface_area, owner_structure_type, status, created_at)
    VALUES ('$SITE_ID', '${4:-QA 06 $1 ${3:-FRICHE} $RANDOM}', '${5:-$USER_ID}', '$1', '${3:-FRICHE}', 1000, 'company', '$2', now() - interval '36 hours');"
  echo "$SITE_ID"
}
# Move a site's creation into the past: age_site <site id> <hours> [minutes].
age_site() {
  psql "$DB" -At -c "UPDATE sites SET created_at = now() - interval '$2 hours ${3:-0} minutes' WHERE id = '$1' RETURNING created_at;"
}
site_name() { psql "$DB" -At -c "SELECT name FROM sites WHERE id = '${1:-$SITE_ID}';"; }
archive_site() { curl -s -b "$JAR" -o /dev/null -w '%{http_code}\n' -X POST "http://localhost:3001/api/sites/${1:-$SITE_ID}/archive"; }
# Create an express project on a site through the real API: add_project [site id]. Sets and prints PROJECT_ID.
add_project() {

# A site's first-project-reminder rows: status | attempts | related_entity_id | sent_at | error_message
pr_rows() {
  psql "$DB" -At -F ' | ' -c "SELECT status, attempts, coalesce(related_entity_id::text, 'NULL'),
      coalesce(sent_at::text, 'NULL'), coalesce(error_message, 'NULL')
    FROM lifecycle_email_deliveries WHERE email_type = 'first-project-reminder' AND related_entity_id = '${1:-$SITE_ID}' ORDER BY created_at;"
}
# All of a user's first-project-reminder rows (any site).
pr_user_rows() {
  psql "$DB" -At -F ' | ' -c "SELECT status, attempts, related_entity_id FROM lifecycle_email_deliveries
    WHERE email_type = 'first-project-reminder' AND user_id = '${1:-$USER_ID}' ORDER BY created_at;"
}
# First project reminder emails MailCatcher holds for an address (and, if given, that site name).
pr_msgs() {
  curl -s http://localhost:1081/messages | jq --arg e "${1:-$EMAIL}" --arg n "${2-}" --arg s "$PR_SUFFIX" \
    '[.[] | (.subject | gsub(" "; " ")) as $subj
          | select(($subj | endswith($s)) and ($n == "" or $subj == ($n + $s)) and any(.recipients[]; contains($e)))]'
}
pr_count() { pr_msgs "$@" | jq length; }
pr_id() { pr_msgs "$@" | jq -r 'max_by(.id) | .id'; }
# Plain-text part of a message, CRs stripped, NBSP turned into plain spaces (checked separately in S4).
plain() { curl -s "http://localhost:1081/messages/$1.plain" | tr -d '\r' | perl -CSD -pe 's/\x{00A0}/ /g'; }

# Whole-line, in-order check: expected lines on stdin, searched in file $1. Prints "<line number>  <line>" or "MISSING  <line>".
in_order() {
  while IFS= read -r line; do
    n=$(grep -nxF -- "$line" "$1" | head -1 | cut -d: -f1); echo "${n:-MISSING}  $line"
  done
}
# Expected plain-text lines: friche_lines <site id> [greeting] and other_lines <site id> [greeting].

# Traces of the dropped compatibility offer (plan D8) in the given files (plain text and/or HTML). Expect 0 for every email.
compat_traces() { cat "$@" | grep -ciE 'compatibilit|Vous ne savez pas encore|evaluer-compatibilite|analyse-de-compatibilite'; }
# The primary CTA line must be followed directly by the contact paragraph: prints "ADJACENT" or "GAP".
cta_then_contact() {
  local a=$(grep -n '^Renseigner mon projet : ' "$1" | head -1 | cut -d: -f1)
  local b=$(grep -nxF 'Et si vous préférez être accompagné dans la prise en main de l’outil, n’hésitez pas à me contacter directement.' "$1" | head -1 | cut -d: -f1)
  # Blank lines between blocks are allowed; any non-blank line in between is a leftover block.
  [ -n "$a" ] && [ -n "$b" ] && [ -z "$(sed -n "$((a + 1)),$((b - 1))p" "$1" | tr -d '[:space:]')" ] && echo ADJACENT || echo GAP
}

# The plan's D2 eligibility, written by hand: which sites the job should pick right now (site id|email).
pcohort() {
  psql "$DB" -At -c "SELECT s.id || '|' || u.email FROM sites s JOIN users u ON u.id = s.created_by
    WHERE s.created_at > now() - interval '72 hours' AND s.created_at <= now() - interval '24 hours'
      AND s.creation_mode IN ('custom', 'express') AND s.status = 'active'
      AND u.lifecycle_emails_unsubscribed_at IS NULL
      AND NOT EXISTS (SELECT 1 FROM reconversion_projects p WHERE p.related_site_id = s.id)
      AND NOT EXISTS (SELECT 1 FROM lifecycle_email_deliveries d
                      WHERE d.user_id = u.id AND d.email_type = 'first-project-reminder' AND d.related_entity_id = s.id)
    ORDER BY s.created_at, s.id;"
}

# Unsubscribe token, as in 03 S9.
SECRET=e2e-tests-unsubscribe-secret
sign() { printf 'v1.%s.%s' "$1" "$(printf '%s' "lifecycle-emails-unsubscribe:v1:$1" | \
  openssl dgst -sha256 -hmac "$2" -binary | base64 | tr '+/' '-_' | tr -d '=')"; }
```

(`tr` lowercases the UUID, as in 03: macOS `uuidgen` prints uppercase.) Offsets are measured from the database clock (`now()` in `age_site`), the window from the `api` container's clock. They are the same machine; the few seconds the job takes to boot are why the boundary checks in S5 use a 5-minute margin (the exact `>` / `<=` semantics are pinned by integration tests, S17).

The users you `register` here are created **now**: they are never in the first site reminder cohort (it needs a registration 24–72 h old), so the first site reminder cannot interfere with the checks below unless a step backdates the user on purpose.

The job is a new process each time, so an `-e` override (`job -e LIFECYCLE_EMAILS_ENABLED=false`) never touches the running API. If you need a Node one-liner with environment access inside the container, write the script to a file and pipe it in (`dc exec -T api node --input-type=module < /tmp/snippet.mjs`) rather than putting it inline: a local hook blocks commands whose text contains env-access code. The same hook blocks commands that mention env files (S18 steps 1, 4 and 6): save those to a file and run them with `bash < file`.

If Docker access is not available, this guide cannot be run: the job, the sweeper and the per-process overrides all need `docker compose exec`. Fall back on S17's automated tests.

## S0 — Preconditions: the job has both cohorts, the contact is configured, the cohorts are drained

1. The scripts are in the image: `dc exec -T api ls "$JOB" "$SWEEPER" "$PREVIEW"`. Observe: the three paths are printed.
2. The URL and the contact reach the container: `dc exec -T api printenv WEBAPP_URL LIFECYCLE_EMAILS_CONTACT_FIRST_NAME LIFECYCLE_EMAILS_CONTACT_EMAIL`. Observe: `http://localhost:3001`, `Mathilde`, `mathilde.lefevre@example.com`.
3. Cohort against real data, dry run: `pcohort | tee /tmp/pcohort-s0.txt | wc -l`, then `job --dry-run`. Observe:
   - both window lines, in this order: `[DRY RUN] First site reminders: registered after …` then `[DRY RUN] First project reminders: sites created after <T1> and at or before <T2>` (AC "the daily job computes eligible sites in addition to eligible users");
   - one `[DRY RUN] Eligible for first project reminder: siteId=…` line per site, and the listed sites are exactly those of `/tmp/pcohort-s0.txt`: `grep -o 'first project reminder: siteId=[^,]*' /tmp/job.log | cut -d= -f2 | sort | diff - <(cut -d'|' -f1 /tmp/pcohort-s0.txt | sort) && echo SAME` → `SAME`;
   - `[DRY RUN] First project reminder summary: eligible=<wc -l count>, sent=0, …` with every other counter `0`, and a `[DRY RUN] First site reminder summary: …` line too;
   - `exit code: 0`.
4. The window is 72 h → 24 h before the run: copy `<T1>` and `<T2>` from the project window line, then `psql "$DB" -At -c "SELECT '<T2>'::timestamptz - '<T1>'::timestamptz, now() - '<T2>'::timestamptz;"`. Observe: `2 days` and `1 day 00:0x:xx`.
5. Drain: `job`. Observe: in `psummary`, `sent=` equals the dry run's `eligible=`, `failed=0`, `errored=0`; `exit code: 0` (leftover e2e sites; their reminders land in MailCatcher). Then `pcohort | wc -l` → `0`.
6. Drain the sweeper too: `sweep`. Observe: `failed=0`, `abandoned=0`, `errored=0`, `exit code: 0`.

From here on, the cohort holds only the sites you create. Sites you created in earlier scenarios may still be eligible: always check **your** site with `listed`, `pr_count` and `pr_rows`, not only the totals.
