# QA 10 — BEN-12: Project impacts summary email

## Setup and assumptions

Creating a reconversion project (custom wizard or express template, not a duplicate) emails its author the three headline findings of the Synthèse, each linking to the matching analysis. Sources of truth: `.agents/tasks/BEN-12/issue.md` (acceptance criteria, scenarios), `decisions.md` (card copy mirrors the web Synthèse for every variant), `plan.md` (§16 Resolutions are binding). This guide was written **before implementation**, from the plan: names, copy and error messages below are the plan's. If the merged code deliberately differs (a product copy change, a renamed log line), check against the code and record the difference in the Results table instead of failing the step.

The e2e stack (`docker-compose.e2e.yml` + `.env.e2e`, from the repository root) must run an `api` image **built from this branch after BEN-12 was implemented**: `make e2e-up-build` (S0 checks it). Only the `api` image changes; no migration and no new environment variable come with this ticket (plan §0). Apart from that build, the guide never restarts or stops a container, and never runs `make e2e-down -v`.

Fixed facts about this stack, taken from `.env.e2e`, `docker-compose.e2e.yml` and the code:

- Web app / API (proxied by the web container): `http://localhost:3001` (`WEBAPP_URL`). `POST /api/auth/register` registers a user, sends the welcome email inline and sets the `access_token` cookie (`httpOnly`, not `secure` because `NODE_ENV=test`, so curl's cookie jar replays it over http).
- Sites (no auth guard): `POST /api/sites/create-custom`, `POST /api/sites/create-express`. Projects (`JwtAuthGuard`, cookie): `POST /api/reconversion-projects` (custom wizard: `CreateReconversionProjectUseCase`, `creation_mode = custom`), `POST /api/reconversion-projects/create-from-template` (express: `creation_mode = express`; templates `PUBLIC_FACILITIES`, `RESIDENTIAL_TENSE_AREA`, `RESIDENTIAL_NORMAL_AREA`, `NEW_URBAN_CENTER`, `TOURISM_AND_CULTURAL_FACILITIES`, `OFFICES`, `INDUSTRIAL_FACILITIES`, `RENATURATION`, `PHOTOVOLTAIC_POWER_PLANT`), `POST /api/reconversion-projects/:id/duplicate` (`{ newProjectId }`, author only, `creation_mode = duplicated`), `GET /api/reconversion-projects/:id/impacts` (the computation the web Synthèse and, after BEN-12, the email derive from; 50 years by default). The first two publish `reconversionProject.created`; the duplicate route publishes `reconversion-project.duplicated`. Payloads below are copied from the e2e fixtures (`apps/e2e-tests/fixtures/helpers/*.helpers.ts`, `tests/site-update/fixtures.ts`, `tests/project-update/urban/fixtures.ts`).
- Web project pages: `/mes-projets/<id>/apercu` (Synthèse, "Aperçu" tab), `/impacts` ("Évaluation des impacts"), `/analyse-cout-benefice` ("Analyse coût-bénéfice"), `/analyse-couts-evites` ("Analyse des coûts évités") (`apps/web/src/app/router.ts`).
- MailCatcher UI/API: `http://localhost:1081`. It is never purged: always look messages up by recipient **and** subject.
- Postgres: `postgresql://postgres:e2e-tests-password@localhost:5433/benefriches_e2e_tests_db`. The volume persists across runs.
- Inside the `api` container (working directory `/app/apps/api`, `dist/` built, `shared` resolvable from there): `LIFECYCLE_EMAILS_ENABLED=true`, `LIFECYCLE_EMAILS_UNSUBSCRIBE_SECRET=e2e-tests-unsubscribe-secret`, `WEBAPP_URL=http://localhost:3001`, `MOCK_OFGL_API=true`, `MOCK_PHOTOVOLTAIC_PERFORMANCE_API=true`, `NODE_ENV=test`. The kill switch is read at boot: it cannot be turned off for the running API (one-off scripts accept `dc exec -e` overrides).
- **OFGL risk (plan §13 R3)**: `ComputeReconversionProjectBreakEvenLevelUseCase` calls the OFGL HTTP API (`data.ofgl.fr`, 10 s timeout; an unknown commune or an outage **throws**). `TerritoryModule` swaps in a fake when `MOCK_OFGL_API=true`, but `ReconversionProjectsModule` declares its own plain `OFGLApi` provider, which probably shadows it: the stack may call the real OFGL API from `/impacts` and now from every project creation. S0 and S4 find out which; S15 depends on it.
- Expected email (plan §6): subject `Projet sur <site name> : résultats de votre évaluation`, with a **non-breaking space (U+00A0) before `:`** and the site name whitespace-collapsed; no greeting, no preheader, no map, no image, no contact signature; sections: intro paragraph, date paragraph, card 1 (ZAN, omitted only if no ZAN indicator), card 2 (break-even, always), card 3 (main indicator, omitted when there is none), then the shared unsubscribe footer. Card links (built from `WEBAPP_URL`): card 1 `Voir le détail des impacts` → `/mes-projets/<id>/impacts`, card 2 `Voir l’analyse coût-bénéfice` → `/mes-projets/<id>/analyse-cout-benefice`, card 3 `Voir l’analyse des coûts évités` → `/mes-projets/<id>/analyse-couts-evites`. Evaluation date = the project's `created_at`, in French, Europe/Paris time, `1er` for the first of the month. The ledger row is `email_type = 'project-impacts-summary'`, `related_entity_id = reconversion_projects.id`.
- Preview (plan §9): `--type=project-impacts-summary` sends two samples (favourable and unfavourable) for the sample project `Habitation, école et commerce` on `Ancienne carrière d’argile de Blajan` (id `00000000-0000-4000-8000-000000000003`, created `2026-06-15T10:00:00Z`); `--project-id=<id>` (only with that type) sends one email rendered from that real project, still with the sample user's unsubscribe link. Neither writes a ledger row nor reads the kill switch.

### Card copy reference (plan §6.4)

Plain text: blocks separated by a blank line, in this order: `[0]` intro, `[1]` date, `[2]` card 1, `[3]` card 2, `[4]` card 3, `[5]` footer. A card block is `headline` / `title` (cards 2 and 3 only) / `body` / `<link label> : <url>`, one per line. Copy uses curly apostrophes `’`.

- Intro: `Voici les résultats de l’évaluation socio-économique du projet « <project name> » sur le site « <site name> ».`
- Date: `Évaluation réalisée le <d mmmm yyyy>` (e.g. `15 juin 2026`, `1er juillet 2026`).

Formats (web `formatNumber.ts`, reproduced in the API): money = rounded to the euro, sign `+`/`-` (none for 0), thousands separated by U+202F, U+00A0 before `€` (`+1 087 355 €`); percent = integer, no space (`13%`); surface = up to 2 decimals, comma, `㎡` (`20 000 ㎡`); number = up to 2 decimals.

Deliberate differences from the web Synthèse (plan D5, decisions.md): the email uses `’` where the web has `'` (`d’espaces`, `l’analyse`); three web typos are fixed in the email only: `est imperméabilise` → `imperméabilise`, `bilan économiques` → `bilan économique`, `annelle` → `annuelle`. Differences from the mockup (`.agents/tasks/BEN-12/attachments/01-04-project-impacts-summary.png`): no map (struck through), subject uses the site name as typed (no `l’` article), card 2 title singular `Coût de l’opération compensé`, card 3 body from the app (`grâce à la reconversion de la friche`).

```bash
# Impacts summary emails held for an address (and, if given, that site name as it appears in the subject), oldest first.
sum_msgs() {
  curl -s http://localhost:1081/messages | jq --arg e "$1" --arg n "${2-}" --arg s "$SUFFIX" \
    '[.[] | (.subject | gsub(" "; " ")) as $subj
          | select(($subj | startswith("Projet sur ")) and ($subj | endswith($s))
                   and ($n == "" or $subj == ("Projet sur " + $n + $s)) and any(.recipients[]; contains($e)))] | sort_by(.id)'
}
sum_count() { sum_msgs "$@" | jq length; }
sum_id() { sum_msgs "$@" | jq -r 'max_by(.id) | .id'; }
# Wait up to 10 s for <count> summary emails: wait_sum <count> <address> [site name]. Prints the count reached.
wait_sum() {
  local i=0 c
  while :; do c=$(sum_count "${@:2}"); { [ "$c" -ge "$1" ] || [ "$i" -ge 10 ]; } && break; i=$((i + 1)); sleep 1; done
  echo "$c"
}
# Newest message to address $1 whose subject (NBSP turned into a space) starts with $2 (09's helper).
msg_id() {
  curl -s http://localhost:1081/messages | jq -r --arg e "$1" --arg s "$2" \
    '[.[] | select((.subject | gsub(" "; " ") | startswith($s)) and any(.recipients[]; contains($e)))] | max_by(.id) | .id'
}
# save <message id> <name>: $QA/<name>.raw.txt (plain part, CRs stripped), $QA/<name>.txt (same, NBSP and U+202F turned
# into spaces), $QA/<name>.html, $QA/<name>.json (MailCatcher metadata).
save() {
  curl -s "http://localhost:1081/messages/$1.plain" | tr -d '\r' > "$QA/$2.raw.txt"
  perl -CSD -pe 's/[\x{00A0}\x{202F}]/ /g' "$QA/$2.raw.txt" > "$QA/$2.txt"
  curl -s "http://localhost:1081/messages/$1.html" | tr -d '\r' > "$QA/$2.html"
  curl -s "http://localhost:1081/messages/$1.json" > "$QA/$2.json"
}
# The plain-text blocks of a saved message, numbered [0], [1], …
blocks() { awk 'BEGIN { RS = ""; n = 0 } { print "[" n++ "]"; print }' "$QA/$1.txt"; }
# Every link of a saved message: the HTML hrefs, then the URLs of the plain-text part.
links() {
  echo "-- html"; tr -d '\n' < "$QA/$1.html" | grep -oE 'href="[^"]*"'
  echo "-- text"; grep -oE '(https?|mailto):[^ ]+' "$QA/$1.txt"
}
# No image, map, chart or flexbox: prints "img=0 media=0 flex=0" when clean.
no_media() {
  echo "img=$(grep -ci '<img' "$QA/$1.html") media=$(grep -ciE '<svg|<canvas|<iframe|<video|<object|<picture|background-image|data:image|cid:' "$QA/$1.html") flex=$(grep -Eic 'display:\s*(flex|grid)' "$QA/$1.html")"
}
# Rendering leftovers: prints "0" when clean.
leftovers() { cat "$QA/$1.txt" "$QA/$1.html" | grep -cE 'undefined|NaN|Valeur invalide|\[object|\{\{|\$\{'; }
# Whole-line, in-order check (06's helper): expected lines on stdin, searched in file $1. Prints "<line number>  <line>" or "MISSING  <line>".
in_order() {
  while IFS= read -r line; do
    n=$(grep -nxF -- "$line" "$1" | head -1 | cut -d: -f1); echo "${n:-MISSING}  $line"
  done
}
# The lines every summary has, card text aside: fixed_lines <project id> <project name> <site name> <date> [card 3: yes|no]
fixed_lines() {

# The shared derivation the email must use (issue "Evaluation period note"), run in the api container on GET /impacts:
# derive <project id> [evaluation period override]. Prints period, zanCompliance, breakEven, mainImpactIndicator.
derive() {

# Republish the project-created event from a one-off process in the api container (same env as the API, kill switch on):
# replay <project id> <site id> <user id>. Prints the exit code and the relevant log lines.
replay() {
  cat > "$QA/replay.mjs" <<EOF
import { NestFactory } from "@nestjs/core";
import { AppModule } from "/app/apps/api/dist/src/app.module.js";
import { RealEventPublisher } from "/app/apps/api/dist/src/shared-kernel/adapters/events/publisher/RealEventPublisher.js";

  await app.get(RealEventPublisher).publish(
    createReconversionProjectCreatedEvent(crypto.randomUUID(), { reconversionProjectId: "$1", siteId: "$2", createdBy: "$3" }),
  );
  console.log("QA10 replay published");

  await app.close();
}
EOF
  dc exec -T api node --input-type=module < "$QA/replay.mjs" > "$QA/replay.log" 2>&1; echo "exit code: $?"

}
# Run the retry sweeper inside the api container: sweep [-e VAR=value ...]. Prints its summary line and exit code.
sweep() {
  local opts=()
  while [ "$1" = "-e" ]; do opts+=(-e "$2"); shift 2; done
  dc exec -T "${opts[@]}" api node "$SWEEPER" > "$QA/sweep.log" 2>&1; local rc=$?; perl -pi -e 's/\e\[[0-9;]*m//g' "$QA/sweep.log"
  grep -E 'retry summary|Retry failed' "$QA/sweep.log"; echo "exit code: $rc"
}
# Run the preview script inside the api container: preview [-e VAR=value ...] <args>. Output in $QA/preview.log.
preview() {
  local opts=()
  while [ "$1" = "-e" ]; do opts+=(-e "$2"); shift 2; done
  dc exec -T "${opts[@]}" api node "$PREVIEW" "$@" > "$QA/preview.log" 2>&1; local rc=$?; perl -pi -e 's/\e\[[0-9;]*m//g' "$QA/preview.log"
  grep -E 'preview|Usage|--project-id|reconversion project|could not be computed|Valid types' "$QA/preview.log"; echo "exit code: $rc"
}
# api container log lines since T0 matching a pattern (default: OFGL and the summary's own lines).
api_logs() { dc logs --no-log-prefix --since "$T0" api 2>&1 | perl -pe 's/\e\[[0-9;]*m//g' | grep -E "${1:-OFGL|[Pp]roject impacts summary}"; }
# Unsubscribe token (03 S9): sign <user id>; unsubscribe <user id> prints the HTTP status.
sign() { printf 'v1.%s.%s' "$1" "$(printf '%s' "lifecycle-emails-unsubscribe:v1:$1" | \
  openssl dgst -sha256 -hmac "$SECRET" -binary | base64 | tr '+/' '-_' | tr -d '=')"; }
unsubscribe() { curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API/lifecycle-emails/unsubscribe" -H "Content-Type: application/json" -d "{\"token\": \"$(sign "$1")\"}"; }
```

(`tr` lowercases the UUIDs: macOS `uuidgen` prints uppercase.)
