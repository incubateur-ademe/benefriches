## Preconditions

- Fresh e2e stack running: from the repo root, run `make e2e-up-build`. This serves the app at `http://localhost:3001`.
- No pre-existing user or seeded data is required — this guide creates a new account through the real signup UI, which is the same path the `bienvenue` heading depends on (`selectCurrentUserFullName` reading the just-created user's `firstName`/`lastName`).
- Do not seed the user via `createTestUserViaApi` / `POST /api/auth/register` (used by `apps/e2e-tests/fixtures/auth.fixtures.ts`) for this check — per `apps/e2e-tests/CLAUDE.md`, the API client is for seeding _pre-conditions_, and here the signup flow itself is the thing under test.

## 1. Start the e2e stack

1. From the repo root, run `make e2e-up-build` and wait for it to report the stack is ready.
2. Open `http://localhost:3001/`. **Expected:** the Bénéfriches home page loads.

## 2. Sign up a new user with a distinctive name

1. On `http://localhost:3001/`, click the **"Commencer"** link. **Expected:** URL becomes `/acceder-a-benefriches`.
2. Click **"Créer un compte"**. **Expected:** URL becomes `/premiers-pas/identite`.
3. Fill the form:
   - **Email**: a unique address, e.g. `qa-06-<random digits>@mail.com`
   - **Prénom**: `Aïcha`
   - **Nom**: `Nguyen`
   - **Type de structure**: `Autre`
   - **Nom de la structure**: `QA Test`

   (Use a first/last name that is obviously _not_ "Grégoire Bailleux" or "Mintsa" — this proves the heading is built from the real signed-up user, not a leftover hardcoded string.)

4. Check the **"J'ai lu et j'accepte que l'ADEME collecte mes données..."** checkbox.
5. Click the **"Commencer"** button. **Expected:** the URL becomes `/premiers-pas/bienvenue`.

## 3. Verify the personalized welcome heading and body copy (step 1)

1. On `/premiers-pas/bienvenue` (reached in step 2), read the page heading. **Expected:** it reads exactly **"Bonjour, Aïcha Nguyen !"** — not "Bonjour, je suis Mintsa !" and not "Bonjour, Grégoire Bailleux !".
2. Read the paragraph directly under the heading. **Expected:** it reads exactly **"Je m'appelle Mintsa Petit-Lambert et je suis chargé de déploiement chez Bénéfriches."**
3. Read the next paragraph. **Expected:** it reads exactly **"Nous allons passer un petit moment ensemble pour évaluer les impacts socio-économiques liés à votre projet d'aménagement."**
4. Confirm neither paragraph reads "Une question ? Contactez-moi directement via la messagerie." and no button labeled **"Contacter Mintsa"** is required to be present for this check — that paragraph/button pair only renders when Crisp is configured (`WEBAPP_CRISP_WEBSITE_ID` is empty in this stack's `.env.e2e`, so it is expected to be absent here). If a third paragraph and a "Contacter Mintsa" button _are_ visible, it should read exactly **"À tout moment, vous pouvez me contacter pour une démo de l'outil via le bouton message en bas à droite de votre écran."**

## 4. Verify the speech bubble styling on step 1

1. Still on `/premiers-pas/bienvenue`, right-click the white box containing the welcome text and choose **Inspect**.
2. In the browser devtools "Computed" panel for that box, check:
   - `background-color` is white (`rgb(255, 255, 255)`)
   - `border` is `1px solid rgb(221, 221, 221)` (`#DDDDDD`)
   - `border-radius` is `8px`
   - `padding` is `16px` on all sides
3. Resize the window to a desktop width (≥ 768px, e.g. maximize the browser). **Expected:** a small diamond-shaped arrow/connector is visible on the left edge of the bubble, roughly level with the top of the avatar, pointing toward the avatar.
4. Narrow the window below 768px wide. **Expected:** the arrow/connector disappears and the avatar stacks above the bubble.

## 5. Verify the avatar styling on step 1

1. Still on `/premiers-pas/bienvenue`, look at the circular avatar to the left of (desktop) or above (mobile) the speech bubble.
2. Inspect it in devtools. **Expected:** it is a circle exactly `60px` wide and `60px` tall.
3. Look at its content. **Expected per the ticket's acceptance criteria: the real Mintsa avatar photo/illustration.** Note what is actually rendered — if it still shows placeholder initials ("MP") on a plain colored circle instead of a photo, flag this as not meeting the "real Mintsa avatar image" acceptance criterion.

## 6. Verify the progress indicator styling and value on step 1

1. Still on `/premiers-pas/bienvenue`, look at the row of segments above the speech bubble (it has `role="progressbar"` and `aria-label="Étape 1 sur 3"` — you can confirm the label by inspecting the element or via an accessibility tree tool).
2. Inspect one segment in devtools. **Expected:** `height` is `8px` and `border-radius` is `4px`.
3. Look at the colors. **Expected:** the 1st segment (current step) is dark blue (`#000091`), the 2nd and 3rd segments (upcoming) are light grey (`#EEEEEE`).

## 7. Advance to step 2 and verify the methodology heading and body copy

1. Still on `/premiers-pas/bienvenue`, click **"Suivant"** in the bottom bar. **Expected:** URL becomes `/premiers-pas/methodologie`.
2. Read the heading. **Expected:** it reads exactly **"Avant de commencer, petit point méthodo."**
3. Read the body paragraph. **Expected:** it reads exactly: **"Il est important de rappeler que Bénéfriches est le seul outil qui permette de calculer les impacts socio-économiques et environnementaux d'un projet d'aménagement. L'outil est développé par l'ADEME depuis 2023, il a été testé auprès de plus de 150 personnes (collectivités, DDT, EPF, développeurs photovoltaïques...) pour s'assurer de sa pertinence. Bénéfriches prend en compte un grand nombre de données pour vous offrir une vision complète des impacts de votre projet : sur les finances de la collectivité, l'emploi, la qualité de vie des riverains, l'environnement, etc. Vous souhaitez en savoir plus sur le mode de calcul ? On vous dit tout dans cette notice."**
4. Confirm **"cette notice"** is still rendered as a plain link at the end of that paragraph (it is expected to still go nowhere real — that link destination is explicitly out of scope for this ticket).
5. Confirm the old placeholder strings are gone: the heading does **not** read "Une méthodologie éprouvée", and the body does **not** contain "Bénéfriches est un outil développé par l'ADEME depuis 2023." as a standalone sentence.

## 8. Verify the progress indicator advances on step 2

1. Still on `/premiers-pas/methodologie`, look at the progress segments. **Expected:** the 1st and 2nd segments are dark blue (`#000091`), the 3rd is light grey (`#EEEEEE`) — same `8px` height / `4px` radius as step 1.
2. Confirm a **"Retour"** button is now visible in the bottom bar (absent on step 1).

## 9. Go back to step 1 and confirm the heading is still personalized

1. Still on `/premiers-pas/methodologie`, click **"Retour"**. **Expected:** URL becomes `/premiers-pas/bienvenue` again.
2. Read the heading again. **Expected:** still exactly **"Bonjour, Aïcha Nguyen !"** (confirms the name isn't only computed once at signup and then lost/hardcoded on revisit) and **no "Retour" button is present** (first step).

## 10. Run the automated checks

From the repo root:

1. `pnpm --filter web test` — **Expected:** all tests pass, including `OnboardingWelcomePage.spec.tsx`'s new "shows a heading personalized with the current user's name" test.
2. `pnpm --filter web typecheck` — **Expected:** no errors.
3. `pnpm --filter web lint` — **Expected:** no errors.
4. `pnpm --filter e2e-tests test:headless tests/onboarding/` (stack from step 1 must still be running) — **Expected:** all tests in `onboarding.spec.ts` and `onboarding-steps.spec.ts` pass, including the updated heading assertions (`Bonjour, ${testUser.firstName} ${testUser.lastName} !` and `Avant de commencer, petit point méthodo.`).
