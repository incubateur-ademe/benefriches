## QA guide — Ticket 04: Step 3 Témoignages content

**Scope**: verify `/premiers-pas/temoignages` shows the real testimonials carousel (not the
ticket-01 placeholder), that its content matches the home page's testimonials section exactly,
and that the home page section still behaves the same after the extraction.

**App under test**: http://localhost:3001 (both `apps/web` and `apps/api` reachable through this
origin).

### Preconditions — create and load an authenticated session

This flow requires an authenticated user (`RequireAuthenticatedUser` guard on the `/premiers-pas/*`
step routes). Create one the same way the e2e suite does — via `createTestUserViaApi` in
`apps/e2e-tests/fixtures/auth.fixtures.ts`, which calls `POST /api/auth/register` and reads the
session cookie off the response — rather than clicking through the multi-field signup form.

1. **Create a test user via the registration endpoint.** Run:

   ```bash
   USER_ID=$(uuidgen)
   curl -i -X POST http://localhost:3001/api/auth/register \
     -H "Content-Type: application/json" \
     -c /tmp/benefriches-qa-cookies.txt \
     -d "{
       \"id\": \"$USER_ID\",
       \"email\": \"qa-temoignages-$USER_ID@mail.com\",
       \"firstName\": \"Jean\",
       \"lastName\": \"Dupont\",
       \"structureType\": \"company\",
       \"structureActivity\": \"other\",
       \"structureName\": \"ADEME\",
       \"personalDataStorageConsented\": true,
       \"personalDataAnalyticsUseConsented\": false,
       \"personalDataCommunicationUseConsented\": false,
       \"subscribedToNewsletter\": false
     }"
   ```

   **Expected**: HTTP `201` response, and a `Set-Cookie: access_token=...` header in the response
   (also saved to `/tmp/benefriches-qa-cookies.txt`).

2. **Load that session in the browser.** Open a browser at http://localhost:3001, open dev tools →
   Application/Storage → Cookies → `http://localhost:3001`, and add a cookie named `access_token`
   with the value captured in step 1 (path `/`). (If driving a browser programmatically, e.g.
   Playwright, call `context.addCookies(...)` with that same name/value — this is exactly what
   `authenticatedPage` does in `auth.fixtures.ts`.) Then load http://localhost:3001/mes-evaluations.

   **Expected**: the "Mes évaluations" page loads directly — no redirect to a login/identity page.
   This confirms the session is authenticated before touching onboarding.

### Step 3 shows the real testimonials content, not the placeholder

3. Go directly to http://localhost:3001/premiers-pas/temoignages (typed in the URL bar — this
   route is intentionally not linked from anywhere yet, same as ticket 01).

   **Expected**: the page loads (no redirect), showing a 3-segment step progress indicator with
   the 3rd segment active, a "Retour" link, and a "Commencer" button in the sticky bottom bar.

4. Read the heading inside the speech bubble at the top of the page.

   **Expected**: heading reads exactly "Ils ont testé et approuvé Bénéfriches". The old
   placeholder heading "Ils nous font confiance" and body text "Contenu à venir : ce texte est un
   espace réservé et sera remplacé par le contenu définitif dans un prochain ticket." are gone —
   search the page for "espace réservé"; it should not be found.

5. Below the heading, look at the first testimonial card in the carousel.

   **Expected**: a card showing the Coop Habitat Bourgogne logo, badge "🏡 Projet urbain", the
   quote starting "L'outil Bénéfriches m'a permis d'objectiver l'impact de nos opérations sur le
   foncier…", and the author line "Cyril Lagarde, Directeur général". This card has no
   "Télécharger le cas d'étude" button (no case-study file for this testimonial).

6. Click the "Témoignage suivant" button (right arrow, next to the carousel).

   **Expected**: the carousel scrolls horizontally and the second card becomes visible — Grand
   Paris Sud Est Avenir logo, badge "🏢 Zone d'activité économique", author "Alice Sapir,
   Responsable d'opérations", and a "Télécharger le cas d'étude" button. The row of dot indicators
   below the carousel updates so the 2nd dot is filled black instead of the 1st.

### Same content and behavior as the home page (no duplication regression)

7. Open a new tab at http://localhost:3001/ (no auth needed — it's a public page) and scroll to
   the "Ils sont convaincus par Bénéfriches" section (below the "how it works" and "data sources"
   sections).

   **Expected**: the same 4 testimonials, in the same order, with identical quotes, authors,
   project-type badges and logos as on `/premiers-pas/temoignages` (Coop Habitat Bourgogne / Cyril
   Lagarde first, Grand Paris Sud Est Avenir / Alice Sapir second, then Balaruc-les-Bains and Melun
   Val de Seine).

8. On this home page section, click the right-arrow ("Témoignage suivant") button once, then the
   left-arrow ("Témoignage précédent") button once.

   **Expected**: same horizontal-scroll behavior as on the onboarding page — cards wider than the
   viewport, roughly 2 visible at a time on a desktop-width window, scrolling smoothly to the next
   card and back; the dot indicators track the currently-scrolled card the same way.

### Step 3 navigation still works (regression check, no change expected here)

9. Back on the http://localhost:3001/premiers-pas/temoignages tab, click "Retour".

   **Expected**: URL becomes `/premiers-pas/methodologie` and the "Une méthodologie éprouvée"
   heading is visible.

10. Click "Suivant", landing back on `/premiers-pas/temoignages`, then click "Commencer".

    **Expected**: the browser navigates to `/mes-evaluations` (URL pathname exactly
    `/mes-evaluations`).
